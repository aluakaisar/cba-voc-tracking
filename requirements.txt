# Core analysis and Google Play collection.
#
# Upper bounds are deliberate. Without them pip's resolver has to search the
# whole version space of every package, which on a fresh machine means
# minutes of backtracking and sometimes no solution at all.
pandas>=2.0,<3
numpy>=1.24,<3
scikit-learn>=1.3,<2
matplotlib>=3.7,<4
google-play-scraper>=1.2.4,<2
vaderSentiment>=3.3.2,<4
pytest>=7.4,<9

# Deliberately absent: scipy.
#
# The analysis needs exactly two things from it, Spearman's rho and a
# Theil-Sen fit, and both are short enough to own (src/_stats.py). scipy is a
# 30MB compiled wheel whose version must agree with numpy's, and on Python 3.9
# that agreement is easy to miss: pip will happily spend minutes backtracking
# over numpy/scipy/pandas combinations before failing. tests/test_stats.py
# compares the local implementations against scipy's to 1e-12 wherever scipy
# happens to be installed, and skips those comparisons where it is not.
#
# If you are on an older Python and even this file stalls, these exact pins
# are known to resolve instantly on Python 3.9 and Apple Silicon:
#
#   pip install numpy==1.26.4 pandas==2.2.3 pytest google-play-scraper
#
# Deliberately NOT pinned here: requests.
#
# app-store-scraper 0.3.5 hard-pins requests==2.23.0 (from 2020). Any file
# that asks for both it and a modern requests sends pip into an unbounded
# backtracking search that appears to hang. So the App Store collector's
# dependencies live in requirements-appstore.txt and are installed separately,
# ideally into their own virtual environment. See that file.
#
# beautifulsoup4 is only needed by the ProductReview collector and brings its
# own requests requirement, so it lives there too.
